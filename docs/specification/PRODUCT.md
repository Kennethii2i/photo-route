# 製品仕様

## 目的と利用者

Photo Routeは、旅行写真の撮影地点を地図で見返し、同じ旅行内で写真をアルバムへまとめる、ブラウザ内で動くローカルファーストのWebアプリです。写真・位置情報を外部へアップロードせず整理したい個人利用を想定しています。アカウント、共有サーバー、旅行経路の推定は提供しません。

## 基本単位

| 概念 | 責務と条件 |
|---|---|
| 旅行 `Trip` | 写真とアルバムの保管範囲。新規ファイル取り込みでは生存する旅行が必要 |
| 写真 `Photo` | 元メタデータ、補正値、ハッシュ、サムネイル参照を保持。写真原本そのものを保存するレコードではない |
| アルバム `Visit` | 一つの旅行内の任意の写真集合。空を許容し、写真1枚を複数アルバムで利用できる |
| 所属 `PhotoAlbumLink` | `[albumId, photoId]`で写真とアルバムを結ぶ唯一の所属正本 |
| 旅行未設定の写真 | 既存の`Photo.tripId === null`の互換閲覧区分。アルバム未所属とは異なる。自動移動しない |

根拠: [モデル](../../src/domain/model.ts)、[新規取り込み](../../src/application/import-photos.ts)、[ストレージ](../../src/infrastructure/storage.ts)。旅行を廃止した全写真ライブラリや、旅行横断アルバムの仕様ではありません。

## 主要シナリオ

1. 旅行を作成・選択し、写真一覧の＋からファイルを取り込む。
2. 日付別写真一覧、ファイル名・日付・GPS・所属条件で写真を探す。
3. 写真を選び、プレビュー、詳細、地図上の位置を確認する。再選択で解除する。
4. アルバム一覧の＋で空アルバムを作り、必要なら「写真を選択」で追加する。
5. アルバムの「地図で見る」で、そのアルバムのGPS付き写真だけを表示する。
6. 誤操作を避ける確認を経てごみ箱へ移し、管理画面から復元する。
7. メタデータ・所属・サムネイルをZIPへ保存し、別環境で検証して復元する。

詳細は[機能一覧](FEATURES.md)と[UI/UX](UI_UX.md)に集約します。

## データの扱い

- 保存するもの: 元のExif関連値、解析済みGPS/日時、手動補正、元バイト列のSHA-256、安定ID、サムネイル、所属、ジョブ、復旧履歴。
- 保存しないもの: 取り込み完了後の元の高解像度写真バイト列。写真原本は利用者が別途保管します。原本の削除・変更は行いません。
- IndexedDBはブラウザプロファイルとオリジンに依存します。データがクラウド同期される仕様ではありません。ZIPも原本のバックアップではありません。
- 背景地図は起動時にOpenFreeMapへ通信します。「すべてオフライン」「外部通信なし」を保証する製品ではありません。[プライバシー](SECURITY_PRIVACY.md)を参照してください。

## 現在の対象外

手動カバー保存、写真メモ保存、写真原本ビューア、旅行間の既存写真移動、旅行名変更、全履歴を表示するUndo UI、自動分類・自動位置補正・自動時差推定、端末間自動同期は実装されていません。内部APIがあることと一般UIで実行できることを区別します。[制約](KNOWN_LIMITATIONS.md)に根拠を記載します。
