# Phase 0 synthetic image fixtures

Run `npm run fixtures:generate` with Python 3.12 and Pillow 10.4.0. Run
`npm run fixtures:check` to compare generated bytes and manifest without edits,
then verify signatures, hashes, embedded EXIF values, and safe decoding. The
generator and [manifest](generated/manifest.json) state each expected value and
SHA-256. These expected values are test inputs, **not** application parsing results.

All pixels, timestamps, and coordinates are fabricated by
`tools/generate_fixtures.py`. No third-party or personal photos are used, so
there is no third-party image license. The fixture generation dependency Pillow
10.4.0 reports license `HPND` in its installed package metadata; it is not an
npm dependency. The application code is licensed under MIT; see the root LICENSE. These self-generated fixtures contain no third-party or personal photos. Their provenance and checksums are listed in docs/specification/SAFE_ASSETS.md; the copyright-holder wording and final scope for non-code fixtures must be confirmed by the owner before publication.

`png_oversized_header.png` has a valid signature and IHDR declaring
50,000 × 50,000 pixels, but its image body is intentionally inconsistent.
Use it only for preflight rejection tests; do not decode it. The truncated JPEG
is also intentionally invalid.

P0-T03 adds `png_exif_gps.png` and `webp_exif_gps.webp` with fabricated
DateTimeOriginal, OffsetTimeOriginal, GPS rationals and orientation 6. The
asymmetric `jpeg_orientation2_flip.jpg` carries raw orientation 2 so parser
output can be distinguished from a display-time horizontal flip. All three
are made by the same pinned generator and listed in the base manifest.

## Genuine HEIC/HEIF containers

The two files in [heif/](heif/) are **synthetic**, not device-origin photos.
`tools/generate_heif_fixtures.py` encodes the same fabricated pixel pattern as
HEVC in a real HEIF container. Both files have ISO BMFF major brand `heic` and
compatible brand `mif1`, with `hvc1` and `hvcC` codec markers. The `.heif` file
uses the generic extension but has the same HEIC/HEVC format; it is not a
separate codec family. No JPEG or AVIF was renamed to imitate HEIF.

On Windows with Python 3.12, create an isolated environment and install
`tools/heif-fixture-requirements.txt` from official PyPI, then run
`npm run fixtures:generate:heif` and `npm run fixtures:check:heif` with that
environment's `python` on `PATH`. The pinned tools are Pillow 12.3.0
([MIT-CMU](https://pypi.org/project/pillow/12.3.0/)) and pillow-heif 1.8.1
([BSD-3-Clause](https://pypi.org/project/pillow-heif/1.8.1/)). Their wheels
are not committed or added as web-app dependencies. Byte-for-byte checks were
observed on Windows x64; cross-platform encoder output is not promised.

The [HEIF manifest](heif/manifest.json) records provenance, SHA-256, format,
codec markers, metadata and expected decoded dimensions. In the EXIF-rich
HEIC, raw EXIF orientation is 6. Pillow-heif's Pillow plugin applies the
transform when opening and exposes orientation 1; use standalone `open_heif`
to inspect the source EXIF. The other HEIF file has no EXIF. No device-origin
fixture is present, and compatibility with camera-produced HEIF remains
unverified. The installed FFprobe 7.1.1 could not read either tiny HEIF file;
the libheif decoder opened both. This is a compatibility finding, not proof
of universal decoder support.
